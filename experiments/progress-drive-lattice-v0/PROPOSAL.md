# Visual progress-field development gate v0

`ls20` is explicitly consumed development data.  This run asks whether a
generic progress drive can turn an action-correlated pixel process into actual
level progress after the ordinary component ontology failed.

The mechanism receives only the current frame and the four action-opaque
calibration transitions.  It infers the movement lattice, the substrate
revealed behind the controlled process, reachable overlay anomalies, and
terminal-like anomalies adjoining the reachable field.  It visits reachable
overlays before testing a terminal candidate.  It contains no game ID, color,
coordinate, action meaning, source tag, or fixed route.

Qwen still sees the frame and shared workspace and writes one support-zero live
goal proposal.  Its proposal changes attention only.  The R2 progress drive is
allowed to execute independently, and attribution must report whether Qwen's
semantic family was causally used.

PASS requires level 1 within 24 total actions, exact replay, and a fresh run.
This is a development/mechanism result, never held-out evidence.
