# Insight source map

The authoritative research root is `../../insights`. The primary synthesis is
`../../insights/kaggle/insights.md`; relevant underlying notebook reviews,
forum ledgers, and preserved artifacts are used to audit material claims.

| Experiment decision | Relevant corpus finding | Disposition in v0 |
| --- | --- | --- |
| Treat real actions as scarce commits | Action efficiency is squared; resets and failed actions remain costly | Enforced and cost-reason logged |
| Maintain plural explanations | ARC is world-model acquisition before action selection | Required 2–8 when available; unknown remains valid |
| Optimize progress and information jointly | Useful probes distinguish hypotheses or advance a grounded objective | Executor value case; raw disagreement discounted |
| Preserve raw and symbolic representations | Compact context helps, but parsers can erase animation/transients | Snapshot retains hashes, deltas, frame/animation provenance |
| Query immutable history programmatically | PRO-LONG and Schema show large value from out-of-band complete-history computation | C receives bounded read-only computation over the same snapshot as B |
| Separate verbal and Python Executor arms | Extra deliberation otherwise confounds the Python affordance | Frozen A/B/C estimands |
| Use one physical server with isolated roles | Capability routing should have narrow authority and inspectable dataflow | Separate prompts, cursor, context, and provenance |
| Compare identical states | Unpaired outcomes cannot establish causal action benefit | Frozen decision-25 snapshot and exact branch replay |
| Require typed predictions | Prediction accuracy is the basis of control and failure diagnosis | Executable checkpoint comparator and calibration |
| Preserve action payload and animation evidence | Coordinate actions and transient frames are known implementation traps | Identity packet records both; unsupported cases fail explicitly |
| Freeze verdicts and controls | Current v0 lacked negative controls and a decisive verdict engine | Positive/negative/inconclusive fixtures before live calls |
| Distinguish mechanism from model ceiling | A 4B negative may reflect model capability or insufficient affordance | Separate failure classifications; no post-hoc model switch |
| Freeze before transfer | Development-game success is not sealed transfer evidence | One specimen only; transfer deferred |
| Bound runtime and preserve finalization | Submission capability includes deadlines and clean shutdown | Global deadline plus 30-minute reserve |

## Relevant but deliberately deferred

The corpus also supports executable transition theories, longer model-checked
plans, milestone graphs, cross-level mechanic composition, full complex-action
coverage, post-training, stronger models, and sealed multi-game evaluation.
Those are scientifically relevant but would confound the narrow C-versus-B v0
treatment. They remain roadmap evidence rather than live interventions here.
