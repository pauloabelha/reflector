# Reflector II 2.2 architecture and production migration

R2.2 promotes the R2.1 controller described in [`R2_1.md`](R2_1.md) from an
experiment-local program into the canonical [`src/reflector2/r2`](src/reflector2/r2)
package. R2.1 remains the frozen evidence baseline. R2.2 changes deployment,
semantic-model transport, and control-factorization search; it does not widen
model authority or reinterpret R2.1 results.
R2.3 ProspectPlanner is now implemented as an explicitly selectable
experimental extension to this runtime. It has not replaced R2.2 bounded
planning as the production default.

## Status convention

- **Implemented** means current production source and executable contracts
  cover the behavior.
- **Observed** means a real provider or ARC run produced stored evidence.
- **Inferred** means a mechanism follows from controlled tests or stored
  observations but has not produced the claimed real-game consequence.
- **Prospective** means the design is not yet demonstrated.

The provider-neutral runtime, interchangeable planner boundary, and mocked
transport contracts are implemented. Qwen has been exercised as both the
semantic model and a model-planner proposer. Luna uses the same tested
contracts, but no live Luna planner result is claimed. Neither migration nor
planner integration by itself establishes a score improvement.

## Production boundary

R2.2 production architecture spans these boundaries:

```text
src/reflector2/r2
├── R2.1-derived controller, schema/planner adapter, scratchpad, and compiler
├── R2-owned GoalContract compilation and environment settlement
├── provider-neutral model profiles and transport
├── Kaggle ARC-AGI-3 breadth runner
└── _runtime/ — frozen controller ancestry required by R2.2

src/reflector2/planner
├── controller-neutral problem, result, and backend contracts
├── bounded deterministic search and plan certificates
└── model-planner adapters for Qwen and Luna

arcade/agent.py — loopback-only viewer and playback server for current R2
```

Production imports and manifests do not resolve through `experiments/`. The
experiment directories remain historical evidence and regression material.
`python -m reflector2.r2 --dry-run` emits a content-addressed manifest of the
canonical R2 runtime tree and resolved configuration. The detached planner
package is a production dependency governed by its generic contracts and test
suite; it is not experiment-local code.

## Model-neutral authority

The configured model is always a semantic proposer. R2 owns:

```text
model: propose bounded schemas, explanations, OPEN goal contracts, attention,
       and working notes
R2:    compile, ground, bind, rank, authorize, consolidate, and settle
world: provide observations, transitions, score, support, and refutation
```

Durable `Qwen*` event and field names remain compatibility identifiers in the
inherited R2.1 ledger. They do not imply a Qwen transport. New manifests and
the Arcade surface identify the actual provider, API, profile, and model.

The model-facing workspace contains exactly one WYSIWYG `model_scratchpad`
object with `game_objective`, `explanation`, `goal`, `expectation`, and `notes`
string fields. `game_objective` is the model's current evidence-bound account
of the win/completion condition; `goal` is its current action-free subgoal.
That same stored object is rendered in Arcade and supplied verbatim to ordinary
semantic and deep-consolidation model turns. It remains unverified model state;
R2 still owns compilation, grounding, control, and settlement.

The semantic loop is settlement-synchronous: each newly recorded environment
transition requires one scratchpad revision before another external action.
Requests carry the latest evidence reference, responses are accepted only
against that same reference, and intervening observations coalesce into the
next required revision rather than allowing stale model state to overwrite the
workspace.

## Pluggable planning and control authority

Planning is injected at the boundary between grounded R2 explanations and the
final action ranking. The top-level `reflector2.planner` package imports no R2
modules and owns no perception, identity, evidence, environment transport, or
settlement. R2 converts one situated explanation and its supported
command-scoped effects into a `ControlProblem`; any `PlannerBackend` may return
a bounded `SearchResult`.

The production backends are:

| Backend | Purpose |
|---|---|
| `bounded-best-first-v0` | Deterministic supported-effect search; production default |
| `fallback-only-v0` | Original R2 one-step ranking with no plan intervention |
| `model-qwen` / `model-luna` | Structured model proposal followed by deterministic replay and validation |

The model planners differ only in their `PlanningModel` adapter. They consume
the same generic problem and cannot authorize an action directly. Unsupported
commands, invariant violations, excessive depth, missing milestones, malformed
responses, and over-budget routes fail closed to the original controller.

The authority sequence is:

```text
observed R2 state + supported effects
→ prospective milestone shadows and bounded factorization
→ deterministic certificate validation
→ at most the first exact command becomes PLAN_ELIGIBLE
→ environment executes one command
→ R2 settles the real successor and invalidates the continuation
→ fresh ranking and replanning
```

Prospective states never become observations or empirical support. A confirmed
positive first edge may contribute new settled evidence to the existing
bounded fast path, but its plan certificate and remaining route are removed.
This preserves R2.1's exactly-one-external-action invariant.

The configured control order is:

```text
validated PLAN_ELIGIBLE > PROGRESS_ELIGIBLE
                        > discriminating PROBE_ELIGIBLE > INELIGIBLE
```

Planner configuration lives under `control.planner`. The deterministic default
is explicit in `src/reflector2/r2/config.json`; omitting a backend also resolves
to `bounded-best-first-v0`. Direct construction remains available through the
`PlannerBackend` protocol for alternate implementations.

## Model profiles and budgets

The default `local-qwen` profile preserves the resident OpenAI-compatible Chat
Completions endpoint and exact GGUF tokenizer admission.

The `openai-gpt-5.6` profile uses OpenAI Responses with:

| Dimension | Value |
|---|---:|
| Context window | 1,050,000 |
| Ordinary output reserve | 8,192 |
| Deep-consolidation output reserve | 16,384 |
| Dependency-closed R2 frontier | 12,000 |
| Ordinary reasoning | medium |
| Consolidation reasoning | high |

The exact model ID is independently selectable, so the profile can compare Sol,
Terra, Luna, aliases, or snapshots with the same declared budget contract.

`openai-custom` accepts any OpenAI Responses model capable of image input and
strict JSON-schema output. Unknown limits are never inferred. Context, ordinary
output, consolidation output, and frontier budgets must all be supplied. A
model-specific reasoning setting is optional and omitted by default.

For every request:

```text
canonical R2 turn
→ provider-specific wire translation
→ exact model-side multimodal token count
→ prompt + actual output reserve admission
→ FIFO transport with stable idempotency key
→ bounded transient retry
→ strict JSON parse and unchanged R2 compiler
→ authority only after compilation and grounding
```

Text, messages, image tokens, template structure, and the response schema are
included in OpenAI's exact count. Count results are cached only by the exact
canonical endpoint/payload pair. An unavailable counter fails closed rather
than falling back to character estimates.

## Credentials and reproducibility

Only an API-key environment-variable name enters configuration. The value is
read at request time and is never copied into config, requests, manifests,
results, or model telemetry. The existing `~/inhambu/.env` key can be loaded in
the parent shell:

```bash
set -a
source ~/inhambu/.env
set +a
```

Every Arcade and Kaggle result records non-secret model metadata: provider,
API, exact model, profile, context and generation budgets, frontier budget,
reasoning settings, timeout, and retry count.

## One runtime for Arcade and Kaggle

Agent Arcade:

```bash
python -m reflector2.r2 --arcade --game ar25 \
  --model-profile openai-gpt-5.6 \
  --model gpt-5.6-terra
```

The browser model picker is intentionally reduced to Qwen and GPT-5.6 Luna,
each with server-owned defaults. CLI and Kaggle retain the general model and
budget selection surface. The server validates every browser choice before
starting a worker; each run receives an isolated, immutable selection. The
same row exposes four planner choices: R2.3 Goal Prospect, deterministic
bounded search (the default), original one-step R2, and model-validated
planning. The last choice binds automatically to the selected Qwen or Luna
model adapter, and the effective planner configuration is recorded in the
immutable run manifest.

The right Arcade column presents the planner before the durable workspace.
Its primary view uses control language rather than certificate internals:

```text
NEXT MOVE                  the only action authorized now
PREDICTED IMMEDIATE EFFECT measured local potential change
WHY THIS MOVE              plain-language selection basis
LINK TO LEVEL COMPLETION   MISSING, OPEN, SUPPORTED, or REFUTED
SIMULATED ROUTE            hypothetical continuation, never queued actions
LAST PLAN CHECK            environment confirmation or invalidation
```

Full command IDs, search limits, and the complete factorization remain under a
technical-audit disclosure. The model scratchpad appears only in the left
column; it is not duplicated in the right durable-workspace view.

Kaggle breadth:

```bash
python -m reflector2.r2.kaggle \
  --global-seconds 27300 \
  --per-run-seconds 900 \
  --model-profile openai-gpt-5.6 \
  --model gpt-5.6-terra
```

The parent Kaggle process applies the same model arguments as Arcade. Fresh
workers inherit those resolved environment overrides and call the same
`reflector2.r2.experiment.run_game`; there is no Arcade- or Kaggle-only model
implementation.

## Planner evidence and remaining empirical boundary

The first matched AR25 experiment supports the engineering boundary but not a
control-performance claim. Across forks after actions 12, 13, and 14, the
deterministic planner found eight depth-3/4 plans whose first steps all settled
as predicted. It nevertheless chose exactly the same actions as original R2,
with zero score divergences. A live Qwen planner produced one causally matched
different first action; that action worsened immediate preferred progress,
did not improve score, and took substantially longer to select.

Therefore no implemented planner has demonstrated that it beats original R2
on AR25. The result establishes backend interchangeability, bounded
composition, certificate validation, one-action authority, settlement, and
replanning. It does not establish improved action efficiency, broader ARC
competence, cross-game transfer, or live Luna planner quality. The exact
protocol, artifacts, provenance, and failure analysis are in
[`experiments/r2-2-planner-ar25-v0/RESULTS.md`](experiments/r2-2-planner-ar25-v0/RESULTS.md).

The next useful comparison must begin at a matched state where a planner
actually proposes a different first command. It must hold R2 source, learned
support, explanation digest, game state, and action/time budgets fixed, then
settle that one divergent command in the real environment. Internal route
depth or a repeated known clear without causal divergence is not evidence that
planning improved control.

## R2.3 experimental Goal Prospect extension

### Implemented authority path

R2 owns a minimum structured `GoalContract` joining a candidate local verb
terminal to an environment terminal such as level completion. Model proposals
always compile as `OPEN`; semantic citations are provenance and cannot support
the contract. Only a cited environment settlement can change it to
`SUPPORTED` or `REFUTED`.

`ProspectPlanner` receives a frozen projection of that contract plus R2's
grounded, command-scoped causal effects. It derives a `GoalProspect` containing
bounded terminal reachability, best supported depth, retained factorization
count, weakest-link support and confidence, unresolved preconditions,
identity risk, protected invariants, and expected immediate orientation. A
GoalProspect is a hypothetical summary, never evidence.

The planner may justify a locally adverse move only when an explicit supported
factorization reaches the contracted local terminal. Its certificate can
authorize exactly one `ActionCommand`. After the real successor arrives, R2
settles that first edge, invalidates the remaining route, and replans. With no
active GoalContract, ProspectPlanner deliberately falls back to R2.2 local
milestone behavior.

### Observed and inferred boundary

The non-executing AR25 prefix scan covered 17 recorded decision boundaries.
ProspectPlanner found terminal routes at two boundaries but selected the same
first action as one-step and bounded planning at all 17. There were zero
locally adverse divergences and zero candidate actions executed by the scan.
Only 11 surviving multi-game checkpoints were available; none stored the
grounded explanation, exact effect table, and GoalContract required for a
legitimate fork. No score or level-completion improvement is claimed. Full
results are in
[`experiments/r2-3-prospect-planner-v0/RESULTS.md`](experiments/r2-3-prospect-planner-v0/RESULTS.md).

Controlled tests establish the intended mechanism: when a supported terminal
route requires a temporary local regression, ProspectPlanner selects it; when
the regression is a dead end, it does not. This is an inferred capability of
the test model, not observed ARC usefulness.

### Causal Entity Induction layer

The live AR25 run exposes the next generic limitation. Qwen proposes `align`
and `contact` over decreasing `fit_residual`, and R2 learns supported movement,
but situated roles bind to individual same-value connected regions. Existing
`abductive_compositions` compose schema definitions; they do not bind several
visible region trajectories as one causal spatial entity. The planner is
therefore given a locally improving atomic pair rather than two composite
figures.

R2 now owns a bounded, defeasible `CausalEntityBinding` supported by common
action-conditioned transformation, preserved relative layout, identity
continuity, and explicit transition evidence. Atomic regions and assemblies
implement one `SpatialEntity` geometry interface, so weak reusable potentials
such as `fit_residual` consume either primitive occupancy or assembly union
occupancy. Explanation settlement records a structured causal-scope residual:
a binding that accounts for one region while leaving reliably co-moving
regions unexplained remains partial and requests assembly accommodation.

Candidate induction is sparse: correspondence candidates are bucketed by
settled transformation signature, coherent buckets produce at most one
minimal factorization each, and a fixed beam retains competing granularities.
Two independent environment-cited settlements are required before an assembly
is uniquely role-grounding eligible. Scene-wide common transformations remain
competing global/reference-frame explanations; member breakaway refutes the
larger entity while allowing a subgroup candidate. Exact member binding IDs are
situated identity evidence, not the reusable entity schema identity.

Entity identity and action effect are separate. The stable identity is the
member correspondence plus preserved internal relations; each opaque action
may retain its own translation, invariance, or state-conditioned transform.
Thus inverse transforms under two actions can support one entity instead of
spuriously refuting it. Actual loss of within-transition coherence, including a
member breaking away, refutes that factorization.

#### Production lifecycle

The live runtime has two valid call orders that the induction boundary must
support:

```text
Agent Arcade: fit(before) -> environment action -> fit(after) -> settle(action)
headless:      fit(before) -> environment action -> settle(action) -> fit(after)
```

`fit_frame` therefore preserves the predecessor regions and observation digest
when it stages a successor. `settle_action` selects the boundary matching the
settled predecessor digest and never treats the already-fitted successor as its
own predecessor. If a cached predecessor cannot be trusted, the boundary is
rebuilt from the cited observation rather than permitting a self-comparison.

Settlement first induces against the true before/after correspondence, then
remaps provisional successor member IDs to the atoms in the fitted current
workspace. A newly `SUPPORTED`, unique binding is reified there immediately,
before the next grounding, ranking, or planning cycle. Supported CAE
translations and invariants are also projected into the ordinary
command-scoped effect model; the planner remains unaware of their induction
provenance. Role grounding receives at most one bounded reservation for a
supported assembly. This makes the assembly eligible for competition without
making it preferred, plan-eligible, or externally authoritative.

Only R2 induction creates these bindings. `ProspectPlanner` receives an already
grounded union geometry and remains ignorant of how it was induced. Arcade
renders causal coverage, the candidate frontier, evidence counts, identity
state, action-conditioned effects, and global-motion suppression in a separate
CAE audit box. The runtime stages the successor internally but publishes its
frame, action settlement, and CAE snapshot together. The browser therefore
cannot flicker between a new observation and stale settlement/induction state.

The implementation is game-neutral: it does not hard-code two figures, colors,
member counts, AR25 actions, or a special insertion verb. Generic tests cover
translation, recoloring, scaling, distractors, global motion, breakaway parts,
preserved and violated internal relations, and cases where the correct actor
really is atomic. Goal terminals use the named measurable observable and
structured target. Structurally identical control proposals share a
`GoalControlSignature` even when their lexical verbs differ; genuinely
different targets remain distinct. An OPEN GoalContract is still settled only
by the environment. Arbitrary object permanence remains prospective.

The induction module does not contain AR25, named action tokens, movement
directions, a fixed member count, `FIT`, or `fit_residual`. FIT is a generic
hand-authored potential elsewhere in the ontology: it can consume the union
geometry of a supported assembly, but it is neither evidence for membership nor
an input to CAE formation.

#### Repair verification and evidence limit

The focused CAE, runtime, R2 planner, prospect planner, and Agent Arcade suite
passes 123 tests. The full repository suite reaches only two failures, both
from pre-existing deleted experiment score artifacts: one missing
`parallel-cognitive-workspace-v1-16/artifacts/SUMMARY.json`, and one empty
autonomous-progress result set. These failures are outside the current R2/CAE
path.

A held-out six-transition replay of live run
`run-1786500358332127827`, processed through the real `FrameSchemaObserver` in
Arcade call order, produced the expected defeasible lifecycle. The first two
settlements supported a unique seven-member assembly with inverse vertical
effects; a subsequent breakaway refuted it; the next two settlements supported
a six-member assembly with inverse horizontal effects; an invariant transition
retained that identity. The replay demonstrates predecessor ownership,
action-conditioned identity, immediate reification, and breakaway refutation.
It does not demonstrate a better action choice, level completion, or score.

The audited live ledger had a valid 155-event hash chain, 153 valid referenced
blobs, and no corrupt blobs among 160 stored blobs at inspection time. Qwen's
first structured workspace write was accepted, while later semantic revisions
were rejected by the independent `natural-language-scratchpad-not-revised`
gate. That limits semantic freshness in the observed run but is not evidence
against CAE settlement.

## Remaining empirical boundary

### Mechanism support is not goal support

The semantic-control handoff now records `progress_confirmations` separately
from mechanism `confirmations`. A correctly predicted stationary effect can
therefore strengthen the action-conditioned mechanism without making the
associated potential a useful objective. Two uniquely grounded observations
with non-positive potential progress, no positive progress confirmation, and
no competing progress-supported explanation create a semantic revision signal.
Qwen may revise or replace the proposal; the learned effect remains an R2
fact. This threshold is a generic evidence prior, not a game solution.

Settlement-time semantic projection reads the observer-owned counters rather
than the candidate's pre-action snapshot. Consequently confirmation,
refutation, and nonprogress evidence is visible to the next semantic turn at
the boundary where it was observed. Unit coverage verifies immediate
projection, the two-observation threshold, stationary mechanism preservation,
positive-progress suppression, and protection of a simultaneously supported
competitor.

The first fresh BP35 trace after this repair retained the independently chosen
transfer protocol. Qwen proposed alignment through a custom normalized
boundary residual; R2 grounded it only as `PROBE_ELIGIBLE`. Its first attempted
settlement broke role identity and therefore did not count as nonprogress.
With no intervening code change, the predeclared next lexical game, CD82,
grounded a custom boundary residual and exposed zero-progress counts 1, 2, and
3 immediately after settlement. Qwen retained a structurally different
interior-compatible sibling while removing the failed outline hypothesis, then
retired all goal proposals by turn 7 when no alternative gained support. This
verifies the fail-closed semantic revision boundary across games; it does not
show useful control, completion, or score improvement.

The full repository suite currently has 240 passes. Its sole failure is the
pre-existing missing historical
`experiments/parallel-cognitive-workspace-v1-16/artifacts/SUMMARY.json` fixture.

### Bounded semantic context remains live

Repeated semantic revision on CD82 exposed a separate transport failure at
turn 9: the exact mandatory prompt plus protected output reserve exceeded the
local Qwen context window by 294 tokens. The prior durable note was serialized
three times through overlapping request channels. R2 now sends the exact
five-field `model_scratchpad` once and a separate compact prior projection for
proposal identity, action-alias evidence, questions, citations, and transition
basis. Legacy duplicated replays remain readable.

No current R2 projection, transition evidence, visual causal unit, graph
authority, or output reserve is removed. A live exact rerun admitted and
completed call 10, settled action 10, and began call 11; the previous build
failed while forming the turn-9 request. The full suite now has 240 passes and
the same missing historical artifact failure.

### Mechanics can precede goals

Atomic effect learning is no longer gated on a Qwen-selected actor/target pair.
During ordinary exploration, a predecessor and successor may contribute an
action-conditioned translation or invariance only when correspondence is
UNIQUE in both directions and the two fits select each other. Ambiguous
duplicates, broken identities, disappearances, and non-rigid deformations
remain outside the translation model. Roles
already owned by a semantic explanation use the existing stricter settlement
path and are not counted twice.

A later semantic goal can consume this effect only after its own situated roles
earn UNIQUE identity. “Mechanism supported, identity open” is therefore a
discriminating probe state, never immediate progress authority. A focused
integration trace learns an effect without a goal, probes fresh role identity,
settles it, and only then reaches positive progress/plan eligibility.

The predeclared CN04 transfer run learned mutually unique rigid atomic effects
before any active semantic explanation while CAE independently retained a
three-member coherent-motion candidate. This verifies the mechanics/semantics
handoff, not level completion or score. The full suite now has 244 passes and
the same missing historical artifact failure.

Evidence from several same-type entities in one intervention is pooled before
it reaches the effect model. A unanimous outcome contributes one observation
with `entity_count` retained for audit; heterogeneous deltas contribute no
type-level effect because intrinsic type is demonstrably insufficient. This
prevents a crowd of invariant siblings from outvoting one moved instance and
provides a principled trigger for later role/context induction.

On DC22, the same first transition fell from 32 entity-level effect records to
14 type-level records; agreeing multiplicities of 11 and 8 were retained, and
the genuine 2-cell translation remained. The full suite now has 245 passes and
the same missing historical artifact failure.

R2.2 enables controlled comparisons; it does not establish that a larger model
improves ARC competence. Required next evidence is a matched suite holding R2
source, game order, action/time budgets, and model profile constant except for
the exact model under comparison. Score, valid compilation rate, semantic
pickup, latency, input/output tokens, transport failures, and cost should all
be reported. For Goal Prospect specifically, the next prospective breadth run
must persist frozen `ControlProblem` values, command-scoped effects,
GoalContracts, and all compared rankings at every boundary. The first eligible
divergence should be frozen before executing matched one-step, bounded, and
ProspectPlanner forks from the same saved environment state.
