# Reflector II 2.2

R2.2 promotes the R2.1 controller described in [`R2_1.md`](R2_1.md) from an
experiment-local program into the production [`arcade/r2`](arcade/r2) package.
R2.1 remains the frozen evidence baseline. R2.2 changes deployment and semantic
model transport; it does not widen model authority or reinterpret R2.1 results.

## Status convention

- **Implemented** means current production source and executable contracts
  cover the behavior.
- **Observed** means a real provider or ARC run produced stored evidence.
- **Prospective** means the design is not yet demonstrated.

The provider-neutral runtime and mocked transport contracts are implemented.
Local-Qwen and OpenAI live score comparisons remain observational work; no
model-quality or Kaggle-score improvement is claimed merely from the migration.

## Production boundary

R2.2 owns this complete runtime closure:

```text
arcade/r2
├── Agent Arcade server and playback
├── R2.1-derived controller, schema adapter, scratchpad, and compiler
├── provider-neutral model profiles and transport
├── Kaggle ARC-AGI-3 breadth runner
└── _runtime/ — frozen controller ancestry required by R2.2
```

Production imports and manifests do not resolve through `experiments/`. The
experiment directories remain historical evidence and regression material.
`python -m arcade.r2 --dry-run` emits a content-addressed manifest of the full
production closure.

## Model-neutral authority

The configured model is always a semantic proposer. R2 owns:

```text
model: propose bounded schemas, explanations, attention, and working notes
R2:    compile, ground, bind, rank, authorize, consolidate, and settle
world: provide observations, transitions, score, support, and refutation
```

Durable `Qwen*` event and field names remain compatibility identifiers in the
inherited R2.1 ledger. They do not imply a Qwen transport. New manifests and
the Arcade surface identify the actual provider, API, profile, and model.

## Model profiles and budgets

The default `local-qwen` profile preserves the resident OpenAI-compatible Chat
Completions endpoint and exact GGUF tokenizer admission.

The `openai-gpt-5.6` profile uses OpenAI Responses with:

| Dimension | Value |
|---|---:|
| Context window | 1,050,000 |
| Ordinary output reserve | 8,192 |
| Deep-consolidation output reserve | 16,384 |
| Dependency-closed R2 frontier | 12,000 |
| Ordinary reasoning | medium |
| Consolidation reasoning | high |

The exact model ID is independently selectable, so the profile can compare Sol,
Terra, Luna, aliases, or snapshots with the same declared budget contract.

`openai-custom` accepts any OpenAI Responses model capable of image input and
strict JSON-schema output. Unknown limits are never inferred. Context, ordinary
output, consolidation output, and frontier budgets must all be supplied. A
model-specific reasoning setting is optional and omitted by default.

For every request:

```text
canonical R2 turn
→ provider-specific wire translation
→ exact model-side multimodal token count
→ prompt + actual output reserve admission
→ FIFO transport with stable idempotency key
→ bounded transient retry
→ strict JSON parse and unchanged R2 compiler
→ authority only after compilation and grounding
```

Text, messages, image tokens, template structure, and the response schema are
included in OpenAI's exact count. Count results are cached only by the exact
canonical endpoint/payload pair. An unavailable counter fails closed rather
than falling back to character estimates.

## Credentials and reproducibility

Only an API-key environment-variable name enters configuration. The value is
read at request time and is never copied into config, requests, manifests,
results, or model telemetry. The existing `~/inhambu/.env` key can be loaded in
the parent shell:

```bash
set -a
source ~/inhambu/.env
set +a
```

Every Arcade and Kaggle result records non-secret model metadata: provider,
API, exact model, profile, context and generation budgets, frontier budget,
reasoning settings, timeout, and retry count.

## One runtime for Arcade and Kaggle

Agent Arcade:

```bash
python -m arcade.r2 --arcade --game ar25 \
  --model-profile openai-gpt-5.6 \
  --model gpt-5.6-terra
```

The browser model picker is intentionally reduced to Qwen and GPT-5.6 Luna,
each with server-owned defaults. CLI and Kaggle retain the general model and
budget selection surface. The server validates every browser choice before
starting a worker; each run receives an isolated, immutable selection.

Kaggle breadth:

```bash
python -m arcade.r2.kaggle \
  --global-seconds 27300 \
  --per-run-seconds 900 \
  --model-profile openai-gpt-5.6 \
  --model gpt-5.6-terra
```

The parent Kaggle process applies the same model arguments as Arcade. Fresh
workers inherit those resolved environment overrides and call the same
`arcade.r2.experiment.run_game`; there is no Kaggle-only model implementation.

## Remaining empirical boundary

R2.2 enables controlled comparisons; it does not establish that a larger model
improves ARC competence. Required next evidence is a matched suite holding R2
source, game order, action/time budgets, and model profile constant except for
the exact model under comparison. Score, valid compilation rate, semantic
pickup, latency, input/output tokens, transport failures, and cost should all
be reported.
